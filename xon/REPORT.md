# XON report

Every number in this file comes from a log, an eval file or a gate result. The block between the AUTO markers is

## Where this ran
A Claude Code **cloud container**, not the user's own machine: 4 CPU cores, 15.7 GB RAM, **no GPU**. So only
**Tier A** was trained. Tier B/C configurations are produced by the same sizing code (`xon init --tier B`) and the
M2 gate ran a 101.6M-parameter Tier-B-shaped model for a few steps on CPU as a stability check, but no Tier B or C
model was trained.

## Live vs mock
- **Live (real internet):** a tiny polite crawl of docs.python.org, developer.mozilla.org, www.w3.org and three files
  on raw.githubusercontent.com (30 pages, ~40 requests, robots.txt honored, 2 s per-domain delay); open-dataset pulls
  from the Hugging Face datasets-server (codeparrot/github-code-clean rows filtered to permissive licenses, MBPP
  train split); Python stdlib sources from disk.
- **Mock web (local servers):** robots/Disallow, 429 back-off, 403 demotion, no-train meta, all-rights-reserved
  blocking, PII scrubbing, unsafe-content quarantine, and all image-text pairs (the live seeds yielded no images).
  The M0 and M3 gates use the mock web so they are reproducible offline.
- **Synthetic (license-clean, unlimited):** UI pages rendered in headless Chromium with DOM labels; procedural
  recognition images.

## Incidents
- During the first live crawl a recursion bug (robots.txt fetch -> crawl-delay lookup -> robots.txt fetch) sent 49
  robots.txt requests to docs.python.org at the 2-second per-domain spacing before I stopped it. Fixed, with a
  regression test (`test_robots_fetched_once_without_delay_override`).

### v0.2 incidents (found by testing, fixed)
- **False success:** on a retry the model rewrote its own tests into a bare `import`, and the agent reported a wrong
  `slugify` as passing. Fix: tests are frozen after attempt 1, examples in the task become authoritative asserts,
  and test files without assertions are refused. After the fix the same task honestly ends `ok: false` (the 0.5B
  model cannot write that regex in 3 sampled attempts); a C++ binary search passes on attempt 1.
- **Overfitting patch:** the fix tool returned `total == 50` (passes the tests, wrong for 51). Candidates that turn an
  inequality into `==`/`!=` are now tried after boundary shifts.
- **Noisy gate:** cycle 5's LM was rolled back because code pass@1 moved 0.003 -> 0.000 (one sample of 310), read as a
  100% regression. Rates now have an absolute noise floor of 0.01. Cycle 5's recorded decision was left as is.
- **Starved training:** one M0 run trained at about 1,000 tokens/s instead of 22,000 because my own demo jobs were
  competing for the 4 cores; its scores were invalid and it was rerun alone. Cycles now flag `starved`.

## Promotion gate, recovery and kill switch (observed, not just unit-tested)
- **Cycle 2 was rolled back** by the gate: held-out perplexity regressed 72% (a fixed step budget on 34 new records
  overfit). Its vision net had improved but was discarded with it. Fix: LM and vision are now gated independently;
  LM increments are capped at 3 epochs over the cycle's data with full replay and 0.3x LR.
- **Cycle 3** (run through `xon start --all`): both promoted. LM perplexity 18.80 -> 15.91, UI-detection F1
  0.401 -> 0.555, zero-shot 0.828 -> 0.956.
- **Kill switch under load:** with crawler sleeping and trainer mid-training, `xon stop` halted the trainer 0.19 s
  and the supervisor 0.61 s after the STOP file appeared; the supervisor terminated the crawler; no XON process left.
- OOM, NaN, preemption/resume, disk/bandwidth/request/GPU-hour caps, 429/403 back-off and cold-shard pruning have
  passing tests (`tests/test_lm.py`, `tests/test_governor.py`, `tests/test_crawler.py`, `tests/test_pipeline.py`).
- **Clean-folder install:** `unzip xon.zip && ./scripts/setup.sh` (fresh venv, pinned deps, torch CPU) ->
  `xon doctor` 12/12 -> `xon init && xon start --all`: 19.6 min wall clock, live crawl 33 pages, one cycle, both
  models promoted (ppl 16.88, UI F1 0.296, recognition 0.962, fidelity 0.925, blind bug-fix 0.733). UI F1 is lower
  than the main run because that cycle had no mock-gallery images and a single vision run; run-to-run variance is real.
- Test suite: 57 passed, 0 skipped (including the slow two-process M3 test).

## What the numbers mean
- **Code LM:** under a million parameters, trained for ~10 CPU minutes. Its held-out perplexity falls, it completes
  syntax plausibly, and it solves **0** of the unseen problems (pass@1 = pass@5 = 0). It is useful only as a ranker
  for repair candidates and for short completions. Do not expect it to write programs.
- **Bug fixing** works through search, not the LM: Ochiai fault localization over per-test coverage, generic mutation
  operators on the suspicious lines, every candidate verified by running the tests. The dev bug set was visible while
  I built the tool (100%); the **blind** set, written afterwards and never used for tuning, is the honest number.
- **Design:** contrast ratios are computed (WCAG formula, matches all reference cases), critique finds seeded
  defects, generated pages pass their own contrast checks, and screenshot->HTML reconstruction clearly beats a
  background-only baseline on held-out pages. The fidelity metric is lenient on mostly-blank pages; the
  reconstructions keep layout, colors and text positions but use placeholder text and lose table borders.
- **UI detection** is moderate (F1 around 0.4 at IoU 0.5); small icons are the weakest class.
- **Recognition** is high, but on 10 procedural shape classes; it says nothing about real-world photos.
- **Agent:** without an API key the planner is a rules engine covering build-app / fix-tests / design / critique. It
  does those end to end (M4), and says so for anything else.

## Known limits
- No GPU: Tier B/C untrained; M2 "trains stably for hours" was not exercised.
- Live crawl was deliberately tiny; most volume came from open datasets and synthetic data.
- The NSFW/violence filter is a keyword screen, not a classifier; the private-person image filter relies on captions.
- `from_screenshot` uses placeholder text (no OCR) and the vision->LM bridge is implemented but untrained at Tier A.
- The rules planner does not understand arbitrary tasks.
